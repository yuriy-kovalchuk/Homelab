# L7 HTTP Visibility & Enforcement

> Status: **draft, not started.**

## Goal

Enable HTTP-level observability (and optionally enforcement) across the workload
cluster using Cilium's L7 proxy. Currently all policies are L3/L4 only.

## Options

### A: Pod annotation (per-deployment, inspection-only)

Add to pod template:

```yaml
annotations:
  cilium.io/visibility: "HTTP=80,443"
```

Enables Hubble L7 flow logs on those ports. No policy change, no enforcement.

### B: Kyverno ClusterPolicy (namespace-wide, inspection-only)

Auto-injects the visibility annotation on all pods in labelled namespaces.
One policy, covers everything without touching app manifests.

```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: inject-cilium-visibility
spec:
  rules:
    - name: inject-http-visibility
      match:
        any:
          - resources:
              kinds:
                - Pod
      mutate:
        patchStrategicMerge:
          metadata:
            annotations:
              +(cilium.io/visibility): "HTTP=80,443"
```

Scope to namespaces via `preconditions` or a label selector on the namespace —
e.g. only namespaces with `cilium-l7-visibility: enabled`.

### C: L7-aware CNP rules (inspection + enforcement)

Replace pure-L4 ports with HTTP rules in existing CNPs. Non-HTTP traffic on
those ports would be dropped.

```yaml
toPorts:
  - ports:
      - port: "8080"
        protocol: TCP
    rules:
      http: [{}]   # allow any valid HTTP, block non-HTTP
```

Only worth it if you also want the block.
